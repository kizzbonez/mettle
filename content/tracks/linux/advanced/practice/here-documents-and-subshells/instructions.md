Complete `solution.sh`. The tests run it as `bash solution.sh HOST:PORT ROOT`, and they also
source it to call `render_conf` and `list_pages` on their own (the `BASH_SOURCE` guard at the
bottom is already there).

1. `render_conf HOST PORT ROOT` prints this server block with **one unquoted here-document**,
   so that the shell fills in HOST, PORT, ROOT and PORT + 1 (the site's API server listens one
   port above the site). The nginx variables `$uri` and `$host` must come out exactly as written,
   never replaced by the shell, even though the function has a variable called `host`.

   ```text
   # generated by vhost for HOST
   server {
       listen PORT;
       server_name HOST;
       root ROOT;
       location / {
           try_files $uri $uri/ =404;
       }
       location /api/ {
           proxy_pass http://127.0.0.1:PORT+1;
           proxy_set_header Host $host;
       }
   }
   ```

   Indentation is four spaces per level. ROOT is written exactly as it was given.
2. `list_pages ROOT` prints every regular file whose name ends in `.html`, at any depth below
   ROOT, as a path relative to ROOT that starts with `./`, one per line, sorted with
   `LC_ALL=C sort`. Do the `cd` in a **subshell**: after the call, the caller must still be in
   the directory it started in.
3. In `main`, split the first argument at the colon into `host` and `port` with `IFS=: read -r`
   and a **here-string**. The starter then checks them (status 2 when they are wrong), checks
   ROOT (status 1) and writes `HOST.conf` in the current directory.
4. Read the output of `list_pages` line by line and print `page PATH` for each page, counting
   them. The loop must not run in a pipeline: the count has to survive it, because the last line
   is `wrote HOST.conf for N pages`.

Example, for a site with `index.html`, `about.html`, `blog/first post.html` and `style.css`:

```text
$ bash solution.sh example.org:8080 site
page ./about.html
page ./blog/first post.html
page ./index.html
wrote example.org.conf for 3 pages
$ grep -e listen -e proxy_pass -e try_files example.org.conf
    listen 8080;
        try_files $uri $uri/ =404;
        proxy_pass http://127.0.0.1:8081;
```
